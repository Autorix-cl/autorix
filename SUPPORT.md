# Support

Autorix provides best-effort community support. It has no support SLA, managed
service, incident-response commitment, warranty, or compliance certification.

## Where to ask

| Need | Channel |
| --- | --- |
| Installation, configuration, and usage questions | [GitHub Discussions](https://github.com/Autorix-cl/autorix/discussions) |
| Reproducible defects | [GitHub Issues](https://github.com/Autorix-cl/autorix/issues/new/choose) |
| Security vulnerabilities | [Private security advisory](https://github.com/Autorix-cl/autorix/security/advisories/new) |

Before opening a discussion or issue, check the documentation, existing
reports, and the [known limitations](docs/community.md#known-limitations).

## What to include

For a support request, provide the Autorix version or commit, component,
deployment method, sanitized logs, expected behavior, actual behavior, and
steps to reproduce. Never post access tokens, client secrets, private keys,
passwords, personal data, or production configuration secrets.

Organizations operating regulated or critical workloads remain responsible for
their own incident response, backups, recovery, monitoring, change management,
and risk approvals. See [SECURITY.md](SECURITY.md) for security reporting and
production assurance boundaries.
